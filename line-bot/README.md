# 導鹿 LINE 預約小幫手

旅客點「我要預約導覽」後，小幫手用按鈕一步步問齊資料，最後給一份含參考價的預約摘要。
負責人在聊天室看到時資料已經齊了，只要回一句確認，不用再一題一題問。

## 為什麼這樣做

2026 年 9 月到 11 月的聊天紀錄顯示，白天第一次回覆很快（中位數 3 分鐘），慢的是「來回問資料」：
從旅客第一句話到發出預約摘要，中位數要 110 分鐘、5 則訊息。最常手打的是
「請問預計何時要搭車？有幾位？導覽行程要多久？」（約 60 次）和「方便留手機嗎？」（約 40 次）。

## 旅客會看到什麼

1. 點圖文選單「我要預約導覽」（或打「預約導覽」、從官網其他按鈕傳來「你好，我想預約…」）。
2. 第一句先說「回答 6 個小問題（約 30 秒），導鹿就能直接幫您確認時段」，每題前面有進度（例如「（2/6）」）。
   依序用按鈕回答，每一題都可以直接打字，也都有「找真人」按鈕：
   | 問題 | 按鈕 |
   |---|---|
   | 哪一天 | 選日期（日曆）、今天、明天、還沒決定 |
   | 幾點出發 | 09:00–16:00、其他時間、還沒決定 |
   | 幾位 | 1–10 位、超過 10 位（打字）、旅行社／遊覽車團 |
   | 導覽多久 | 60／90／150 分鐘，按鈕上直接顯示 LINE 95 折參考價 |
   | 在哪上車 | 鹿港生態公園停車場、鹿草路停車場、還不確定，或直接打民宿名稱（上車地點由旅客決定） |
   | 手機 | 打字輸入（註明號碼只用於這次預約） |
3. 收到一則簡短的預約摘要，例如：
   ```
   這是您的預約詢問 🦌

   📅 12/17（四）・時間待確認
   👥 5 位・90 分鐘
   💰 參考價 NT$1,425（LINE 95 折）
   📍 上車：待確認
   📞 手機：0912-345-678

   導鹿會在這裡跟您確認時段與費用，通常幾分鐘內回覆。
   ```
   晚上 7 點到早上 8 點則說「明天早上 8 點後回覆您」。
4. 打字也看得懂日常說法：「三位」「2大1小」「4位大人」「下午兩點」「下週六」「12/20 下午2點」（日期和時間一起打，時間那題就跳過）、「一個半小時」。小孩人數會記在備註。
5. 看不懂時先回「不好意思沒看懂…可以用下面的按鈕選，或打『12/20』這樣的格式」並再附一次按鈕；第二次還是看不懂就交給真人。
6. 旅客在問問題（有「？」「嗎」「請問」「可以」等），或按「找真人」，就交給真人，並一定回一句「收到，我請專人回覆您 🦌」（按鈕是「請直接在這裡留言」），晚上改成說明天早上 8 點後回覆。
7. **旅行社／遊覽車團**：人數那題有這顆按鈕；任何一步打到「旅行社、導遊、領隊、遊覽車、帶團」也一樣。回「導遊與團體有專屬價格，導鹿會請專人報價」，已經回答的日期、時間會保留，負責人收到「🚌 旅行社／遊覽車報價」通知。一般散客 50 位以內照公式顯示參考價，超過 50 位顯示「另外報價」。

從官網「試算」送出的完整預約訊息不會再問一次，只會記到試算表。

## 負責人會收到的通知（推播到個人 LINE）

綁定後，以下三種情況會推一則到負責人的個人 LINE：

- 旅客填完資料：預約摘要（日期、人數、時長、參考價、上車地點、手機）。
- 旅客按「找真人」，或問到一半打了別的問題：「有人想找真人」，附上旅客打的那句話。
- 旅客從官網送出預約：官網預約詢問摘要。

例如：
```
🦌 新預約詢問｜王小明
📅 12/17（四）・10:00
👥 5 位・90 分鐘
💰 參考價 NT$1,425（LINE 95 折）
📍 上車：待確認
📞 手機：0912-345-678
⚠️ 平日
開啟聊天室：https://chat.line.biz/…
```
手機號碼可以直接點來撥打；「開啟聊天室」會打開官方帳號後台這位旅客的對話。

- **晚上不吵**：晚上 7 點到早上 8 點進來的不馬上推，隔天早上 8 點多合成一則（「晚上有 2 筆詢問」）。
- **額度**：推播算在每月 200 則（和群發共用）。過去 30 天約 57 筆預約詢問，加上找真人，估計每月 70–80 則。
  小幫手每月最多推 `PUSH_MONTHLY_LIMIT`（預設 150）則，帳號剩餘額度不夠時也會停推；停推時試算表照樣記錄。
- **綁定**：負責人用自己的 LINE 加官方帳號好友，傳「綁定 綁定碼」（綁定碼在指令碼屬性 `BIND_CODE`）。
  傳「取消綁定」就停止。可以綁多人，但每多一人，每則通知就多算一則額度。

## 負責人要做的事

- 收到通知後，到聊天室確認時段並回覆旅客（跟平常一樣）。
- 每週到試算表「預約詢問」分頁，在「結果」欄選 成交／沒成交／改電話／其他。這樣才量得到真正的轉換率。

回旅客都用免費的「回覆訊息」，只有給負責人的通知會用到推播額度。

## 試算表欄位

編號、收到時間、旅客 ID、旅客名稱、語言、來源（keyword／hello／website）、日期、出發時間、人數、導覽分鐘、
上下車地點、手機、其他需求、參考價、提醒（平日／今天／明天）、狀態（問資料中／資料齊了／交給真人／官網表單）、結果、原始訊息。
同一位旅客的一次詢問只占一列，問到哪就更新到哪。

## 小幫手故障時

上線後「導覽｜預約表單」和「非回應時間｜通用」兩則自動回應會關掉，所以小幫手一壞，旅客就可能收不到任何回應。為此有三層保護：

1. **出錯也會回旅客**：某則訊息處理到一半出錯時，只要還沒回過旅客，小幫手會補回一句 `FALLBACK_TEXT`（「訊息收到，請告訴我們哪一天來、大概幾位…急件請撥 0927-013-167」），並記下錯誤。
2. **每小時自我檢查**（`healthCheck` 觸發）：token 失效、最近有處理失敗、或超過 `STALE_HOURS`（預設 72）小時沒收到任何 LINE 訊息，就寄信給 `ALERT_EMAIL`（沒設就寄給 Apps Script 擁有者），token 還能用時也推一則給負責人請他多留意聊天室。同一個問題 6 小時內只通知一次，恢復正常時再寄一封「已恢復」。
3. **從外面檢查**（GitHub Actions `LINE bot health`，每 3 小時）：Apps Script 整個掛掉（授權過期、部署被刪）時，上面兩層都不會動，這一層會讓 GitHub 的排程失敗，GitHub 會寄信通知。需要在 repo 的 Secrets 設 `LINE_BOT_HEALTH_URL` = `<exec 網址>?key=<WEBHOOK_KEY>&health=1`；沒設就跳過。

**收到警報後（任何人都能做，約 1 分鐘）**：
1. LINE 官方帳號後台 →「自動回應訊息」→ 重新啟用「導覽｜預約表單」，指定時段改成「永遠」。
2. 重新啟用「非回應時間｜通用」。

這樣旅客就回到原本的自動回應，負責人照平常在聊天室回覆。接著修小幫手：看 Apps Script「執行作業」的錯誤訊息；token 過期就到 LINE Developers 重新發行並更新 `LINE_CHANNEL_ACCESS_TOKEN`。修好、收到「已恢復」信之後，再把上面兩則自動回應關掉，避免旅客收到兩則。

## 安裝步驟（約 15 分鐘）

> 所有金鑰都只貼在 Google Apps Script 的「指令碼屬性」，不要貼到聊天室或任何對話裡。

1. **開啟 Messaging API**：[manager.line.biz](https://manager.line.biz) → 帳號 →「設定」→「Messaging API」→「啟用」。**啟用後無法關閉**，但不影響原本的聊天、自動回應、圖文選單與群發。
2. **取得 token**：[developers.line.biz/console](https://developers.line.biz/console/) → 該頻道 →「Messaging API」分頁 → 最下面「Channel access token (long-lived)」按「Issue」。
3. **建立試算表與 Apps Script**：
   1. 新增 Google 試算表 →「擴充功能」→「Apps Script」，把 `Code.gs` 整份貼上，存檔。
   2. 「專案設定」→「指令碼屬性」新增 `LINE_CHANNEL_ACCESS_TOKEN`。
   3. 回編輯器執行 `setup`（第一次會要求授權，包含寄信權限）。會建立「預約詢問」分頁、`WEBHOOK_KEY`、綁定碼 `BIND_CODE`、每天早上推送晚間詢問的觸發，以及每小時的健康檢查。
   4. 「部署」→「新增部署作業」→ 網頁應用程式，執行身分「我」、存取「所有人」，複製 `/exec` 網址。
4. **設定 Webhook**：Messaging API 設定的 Webhook 網址填 `<exec 網址>?key=<WEBHOOK_KEY>`，「回應設定」打開 Webhook，「聊天」維持打開。
5. **設定外部健康檢查**：GitHub repo →「Settings」→「Secrets and variables」→「Actions」新增 `LINE_BOT_HEALTH_URL`（`<exec 網址>?key=<WEBHOOK_KEY>&health=1`），再到「Actions」手動跑一次「LINE bot health」確認是綠的。
6. **調整原本的自動回應**（避免旅客收到兩則）：
   - 關閉關鍵字「我要預約導覽／預約導覽／導覽預約」那則（導覽｜預約表單）。
   - 關閉「非回應時間｜通用」。晚上改由小幫手回同一句「訊息收到」，而且每位旅客一晚只回一次；問完預約的旅客不會再收到。
7. **綁定負責人**：負責人的 LINE 傳「綁定 綁定碼」給官方帳號，收到「綁定完成」即可。
8. **測試**：用另一支手機點「我要預約導覽」，一路按到最後，看是否收到摘要、試算表多一列、負責人收到通知。

改完程式要「部署」→「管理部署作業」→ 編輯 → 版本選「新版本」，網址不會變。

## 可以調整的設定（指令碼屬性）

| 名稱 | 預設 | 說明 |
|---|---|---|
| `INTENT_KEYWORDS` | 我要預約導覽,預約導覽,導覽預約,我想預約,book a tour,booking | 哪些訊息會開始問資料（40 字以內、包含這些字） |
| `TIME_OPTIONS` | 09:00,10:00,11:00,13:00,14:00,15:00,16:00 | 出發時間的按鈕 |
| `PICKUP_OPTIONS` | 鹿港生態公園停車場,鹿草路停車場 | 上車地點的按鈕（逗號分隔）；民宿等其他地點由旅客打字 |
| `REPLY_START_HOUR` / `REPLY_END_HOUR` | 8 / 19 | 真人回覆時段，和官方帳號一致。這段時間外算晚上 |
| `NIGHT_ACK` | 訊息收到 🦌 我們會於下一個 08:00–19:00 回覆時段處理。… | 晚上一般訊息的回覆（換行打 `\n`），清空就不回 |
| `OA_KEYWORDS` | 停車資訊,價格,行程… | 官方帳號關鍵字自動回應已經會回的字，晚上不再加回「訊息收到」 |
| `FLOW_HOURS` | 6 | 問到一半多久沒動作就作廢（最多 6） |
| `PUSH_MONTHLY_LIMIT` | 150 | 小幫手每月最多推幾則給負責人 |
| `BIND_CODE` | （setup 產生） | 負責人綁定用的碼；外流就改掉 |
| `PUSH_TO` | （綁定後自動寫入） | 收通知的負責人 |
| `SHEET_ID` | （空） | 只有程式不是從試算表開的時候才需要 |
| `FALLBACK_TEXT` | 訊息收到 🦌 想預約導覽的話… | 小幫手出錯時回旅客的話 |
| `ALERT_EMAIL` | （空＝Apps Script 擁有者） | 故障警報寄到哪 |
| `STALE_HOURS` | 72 | 超過幾小時沒收到 LINE 訊息就當成異常 |

價錢和官網 `src/data/tours.js` 的 `TOUR_PRICING` 相同；官網改價時，`Code.gs` 的 `PRICING` 也要一起改（測試會檢查兩邊一致）。

## 已知限制

- Google Apps Script 讀不到 LINE 的簽章標頭，所以用網址上的 `WEBHOOK_KEY` 擋掉陌生請求。請不要公開 Webhook 網址；若外流，刪掉 `WEBHOOK_KEY` 再執行一次 `setup`，並更新 Webhook 網址。
- 小幫手看不到負責人在聊天室打的回覆，所以不會判斷「有沒有人回了」。
- 官方帳號新增或修改關鍵字自動回應時，記得同步更新 `OA_KEYWORDS`，否則晚上旅客可能多收到一句「訊息收到」。

本機測試：`node --test scripts/line-bot.test.mjs`。
