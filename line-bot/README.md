# 導鹿 LINE 預約詢問小幫手

讓每一則預約詢問都有人接到，不再「自動回覆完就沒下文」。

## 它會做什麼

1. 旅客從官網送出預約訊息（或按官網的「LINE 預約」按鈕）。小幫手用**免費的回覆訊息**跟旅客說「收到了」。
   - 平日的詢問會多一句「平日導覽員較少，需要多一點時間確認」。
   - 晚上 9 點到早上 8 點的詢問會說「明天早上 8 點後回覆」。
2. 推播一張**詢問卡**給爸爸（主要負責人），上面有日期、時間、人數、接送、參考價。平日、今天、明天的團會標紅色提醒。
3. 卡片下方有四個按鈕：
   | 按鈕 | 小幫手幫你做的事 | 用掉的推播 |
   |---|---|---|
   | 可以接 | 傳「可以安排，稍後確認集合地點與費用」給旅客 | 1 |
   | 不能接 | 傳「這個時段排滿了，可以換時間」給旅客 | 1 |
   | 轉同業 | 傳「正在請合作夥伴支援，確認後回覆」給旅客 | 1 |
   | 我來聊 | 不傳任何訊息，你自己到聊天室回 | 0 |
4. 爸爸 **30 分鐘**沒按，同一張卡自動轉給媽媽（只在早上 8 點到晚上 9 點計時，半夜的詢問從早上 8 點開始算）。
   誰先按就算誰的，另一個人再按會顯示「已經處理過了」，旅客不會收到兩次。
5. 每一筆都寫進 Google 試算表「詢問紀錄」分頁：收到時間、旅客、行程、狀態、誰處理、處理時間、有沒有轉給媽媽。
6. 圖文選單的「預約導覽」也會通知爸爸（只有「我來聊」按鈕，因為還沒有細節）。官方帳號原本的關鍵字自動回應照常運作。

## 推播額度

目前方案每月 200 則推播（群發也算在裡面）。每一則詢問大約用 1 到 2 則：通知爸爸 1 則，按「可以接／不能接／轉同業」再 1 則，轉給媽媽多 1 則。
所以一個月大約可以處理 **100 則詢問**。剩不到 20 則時，卡片上會提醒；用完時，按鈕只會記錄，不會傳給旅客，請直接在聊天室回覆。
在官方帳號聊天室傳「小幫手狀態」可以看到本月還剩幾則。

## 安裝步驟（約 20 分鐘，leon 操作）

> 所有金鑰都只貼在 Google Apps Script 的「指令碼屬性」，不要貼到聊天室或任何對話裡。

### 1. 開啟 Messaging API（LINE Official Account Manager）

1. 到 [manager.line.biz](https://manager.line.biz) → 導鹿帳號 → 右上角「設定」→ 左邊「Messaging API」→「啟用 Messaging API」。
2. 選擇或建立一個「服務提供者」（例如：導鹿）。隱私權政策、服務條款網址可以先空著。
3. **注意：啟用後無法關閉**，但不影響原本的聊天、自動回應、圖文選單與群發。

### 2. 取得 Channel access token（LINE Developers）

1. 到 [developers.line.biz/console](https://developers.line.biz/console/) → 剛剛的服務提供者 → 導鹿的頻道 →「Messaging API」分頁。
2. 最下面「Channel access token (long-lived)」按「Issue」，複製起來，等一下貼到步驟 3。

### 3. 建立試算表與 Apps Script

1. 開一個新的 Google 試算表，命名「導鹿預約詢問」。
2. 上方選單「擴充功能」→「Apps Script」。把 `Code.gs` 的內容整份貼上，取代原本的程式，存檔。
3. 左邊齒輪「專案設定」→ 最下面「指令碼屬性」→ 新增：
   - `LINE_CHANNEL_ACCESS_TOKEN`：步驟 2 複製的 token
4. 回到編輯器，上方函式選單選 `setup` →「執行」。第一次會要求授權，選你的 Google 帳號 →「進階」→「前往（不安全）」→「允許」。
   執行完，「指令碼屬性」會多出 `WEBHOOK_KEY` 和 `BIND_CODE`（6 位數綁定碼），試算表會多一個「詢問紀錄」分頁。
5. 右上角「部署」→「新增部署作業」→ 類型選「網頁應用程式」：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
   - 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。

### 4. 設定 Webhook

1. 回到 LINE Official Account Manager →「設定」→「Messaging API」→ Webhook 網址填：
   `<步驟 3 的 /exec 網址>?key=<WEBHOOK_KEY>`
2. 到「回應設定」：**Webhook 打開**；「聊天」和「自動回應訊息」維持打開。
3. 按「驗證」若出現 302 之類的錯誤可以忽略，這是 Google 網址轉址造成的，實際訊息會正常送到。用下一步的綁定來確認。

### 5. 綁定爸爸和媽媽

爸爸和媽媽要先加導鹿官方帳號為好友，然後各自在跟導鹿的聊天室傳：

- 爸爸：`綁定主要 <BIND_CODE>`
- 媽媽：`綁定備援 <BIND_CODE>`

收到「已綁定為主要負責人／備援」就完成了。之後傳「小幫手狀態」可以檢查設定。

### 6. 測試

用另一支手機（或請朋友）從 [gtourlk.com.tw](https://gtourlk.com.tw/#contact) 填表送出 LINE。應該會：
旅客收到「收到您的預約詢問了」→ 爸爸收到詢問卡 → 按「可以接」→ 旅客收到確認 → 試算表多一列。

## 可以調整的設定（指令碼屬性）

| 名稱 | 預設 | 說明 |
|---|---|---|
| `ESCALATE_MINUTES` | 30 | 幾分鐘沒處理就轉給媽媽 |
| `WORK_START_HOUR` / `WORK_END_HOUR` | 8 / 21 | 轉交計時的時段（台北時間） |
| `DEDUPE_MINUTES` | 30 | 同一位旅客幾分鐘內重複傳，只通知一次 |
| `QUOTA_WARN_LEFT` | 20 | 剩幾則推播時開始提醒 |
| `GUEST_ACK` | on | 改成 `off` 就不自動回覆旅客「已收到」 |
| `INTENT_KEYWORDS` | 預約導覽,我想預約,book a tour,booking | 哪些短訊息也要通知（逗號分隔） |
| `SHEET_ID` | （空） | 只有程式不是從試算表開的時候才需要 |

想改成只通知爸爸：把 `BACKUP_USER_ID` 刪掉就不會轉交。想換人：請他重新傳綁定指令。
改完程式要「部署」→「管理部署作業」→ 編輯 → 版本選「新版本」，網址不會變。

## 已知限制

- Google Apps Script 讀不到 LINE 的簽章標頭，所以用網址上的 `WEBHOOK_KEY` 擋掉陌生請求。請不要公開 Webhook 網址；若外流，刪掉 `WEBHOOK_KEY` 再執行一次 `setup` 換新的，並更新 Webhook 網址。
- 晚上官方帳號原本的「非回應時間｜通用」也會回一則「訊息收到」，所以晚上旅客會收到兩則。要改的話，可以把那則通用回應關掉，或把 `GUEST_ACK` 設成 `off`。
- 試算表的「可以接」不會自動排進 Google Tasks，按完小幫手會提醒你手動排。

本機測試：`node --test scripts/line-bot.test.mjs`（用官網真正產生的訊息測解析、按鈕、轉交與額度）。
